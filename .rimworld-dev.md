# Realistic Bases development settings

Shared workflows are vendored at `.shared/rimworld-dev-skills` and discovered
through `.agents/skills` and `.claude/skills`. Read `.rimworld-dev.json` for this
checkout's project, tests, shipped DLLs, reset save, and baseline active-mod order.
The shared snapshot works after an ordinary clone without a sibling skills repo.
Update it from a clean checkout with:

```sh
sh .shared/rimworld-dev-skills/scripts/update-subtree.sh
```

The default source is the published `RimWorld-mods-patches/rimworld-dev-skills`
repository's `main` branch. Optional source/ref arguments override it.

## Consumer-specific assertions

- Framework/reference pin: net472 / RimWorld 1.6.4871; check the project before changing it.
- Full planner/garrison and layout suites are configured. For focused layout tests,
  append `-- --only P4D` (or another matching name); the full suite takes minutes.
- Only `RealisticBases.dll` belongs in `1.6/Assemblies/`.
- The existing immutable reset point is `RealisticBases-P0-Disposable.rws` under
  `.runtime/rimworld-dev-profile/Saves`. Preserve it. If absent in a fresh clone,
  create a disposable developer colony explicitly; do not import normal saves.
- Require the configured five-mod baseline in the profile and loaded-mod log.
  Optional HugsLib/Geological Landforms/Map Preview tests restore it afterwards.
- Confirm `GAME_LOADED` plus the native autoload/profile log evidence at startup.
- For procedural generation, use exact action `Generate playable flat P4 settlement`
  and fresh `event=PROCEDURAL_SPAWN_COMPLETE\b`, failing on
  `event=PROCEDURAL_(PLAN|SPAWN)_REJECT\b`. A successful API invocation or
  `DEBUG_SETTLEMENT_READY` alone is not acceptance.
- `Use high-industrial P4 stage once` is a synchronous setup action, not generation.
- `Generate isolated hostile P0 settlement` can unload without a player pawn;
  `Generate playable hostile P0 settlement` moves one disposable colonist to keep
  it loaded for tick-based P2/P3 checks. These mutate only the development save.
- `Audit current P3 defensive encounter` must target the encounter map. Verify
  defender bounds/positions, player control, mortar ammunition/barrels, power,
  controller transitions, and save/reload restoration against logs and actual
  pawns, not screenshots alone. Recheck map and pause state after arrival/reload.
- For a fresh single-mortar P4E magazine case, `Start P4E mortar magazine loading
  probe` requires untouched twelve-HE/two-spare-barrel shelf stocks, consumes the
  initial embedded barrel, moves the disposable visitor beyond direct-fire range
  and drafts it, then observes the real funded crew's native jobs. Resume after
  arming; require fresh `P4E_LOGISTICS_PROBE_COMPLETE` with `passed=True`. It
  automatically pauses on success/deadline. Do not leave an undrafted visitor
  running unattended: its death can unload the test map before inspection.
  Use `Audit P4E mortar logistics` and `Show P4E mortar position` while paused.
  Invocation success alone is not a loading pass. Save/reload and compare stack
  IDs/counts plus loaded shells, not just loose-stock counts.
- Quest/native fallback tests have different terminal events; use the bounded
  contracts in `docs/p4d-quest-plan.md` and `docs/p4d-findings.md`, not the procedural
  completion pattern above.

All test profiles, save copies and logs remain ignored under `.runtime/`.
